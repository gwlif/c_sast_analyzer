# AST-анализатор безопасности исходного кода C/C++

**Учебный SAST-инструмент на Python и Clang `libclang`** для поиска потенциально опасных вызовов функций в исходном коде C/C++.

Проект демонстрирует работу с AST, настраиваемыми правилами безопасности, подавлением предупреждений, проверками некоторых случаев переполнения буферов, автоматическими тестами и интеграцией в CI. Это портфолио-проект для изучения AppSec/DevSecOps, а не замена промышленного статического анализатора.

## Возможности

- **Анализ AST через Clang (`libclang`)** вместо простого поиска подстрок в исходниках.
- **Правила из JSON-конфигурации** для вызовов `strcpy`, `sprintf`, `gets`, `system`, `alloca`, `scanf` и других настраиваемых функций.
- **Нормализация встроенных функций Clang**, в том числе защищённых вариантов вроде `__builtin___strcpy_chk`, которые могут встречаться на macOS.
- **Подавление предупреждений по комментариям** с маркерами `// ignore-sec` и `// nosonar`; строки и прочие текстовые литералы сами по себе не считаются комментариями.
- **Исключение каталогов** по именам из конфигурации (по умолчанию `tests/`, `vendor/`, `build/`).
- **Ограниченные проверки буферов** для некоторых простых случаев с фиксированными массивами и строковыми литералами: `strcpy`, `sprintf` и `scanf`.
- **Отчёты JSON, HTML и SARIF 2.1.0** с путём к файлу, строкой, столбцом, фрагментом исходного кода и рекомендацией.
- **Код завершения для CI**: опция `--exit-code` возвращает ненулевой код, если найдены потенциальные проблемы.
- **Автоматические тесты и GitHub Actions**: тестовый запуск, проверка работы с установленным `libclang` и сохранение SARIF-отчёта как артефакта CI.

## Технологии

- Python 3.10+
- Clang AST / `libclang`
- JSON, HTML, SARIF 2.1.0
- `unittest`
- GitHub Actions

## Установка

Из корня репозитория создай виртуальное окружение и установи Python-пакет `libclang`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install libclang
```

Проверь, что Python может загрузить Clang:

```bash
python -c 'from clang.cindex import Index; print(Index.create())'
```

На macOS анализатор дополнительно проверяет распространённые пути установки LLVM через Homebrew. Если `libclang` не загружается, проверь совместимость Python-пакета с библиотекой LLVM и убедись, что активировано нужное виртуальное окружение.

## Быстрый запуск

Просканируй демонстрационный файл и создай JSON-отчёт:

```bash
python analyzer.py security_cases.c \
  --config config.json \
  --format json \
  --out security_report
```

Будет создан файл `security_report.json`. Доступны три формата:

```bash
# JSON
python analyzer.py security_cases.c --config config.json --format json --out security_report

# HTML
python analyzer.py security_cases.c --config config.json --format html --out security_report

# SARIF 2.1.0
python analyzer.py security_cases.c --config config.json --format sarif --out security_report
```

Параметр `--out` задаёт имя файла без расширения. Расширение (`.json`, `.html` или `.sarif`) добавляется автоматически.

Можно анализировать как отдельный файл, так и каталог:

```bash
python analyzer.py ./src --config config.json --format sarif --out sast_report
```

Чтобы завершать CI-задачу с кодом `1`, если найдены предупреждения, добавь `--exit-code`:

```bash
python analyzer.py ./src --config config.json --format json --out sast_report --exit-code
```

### Коды завершения

- `0` — сканирование завершено, либо найденные предупреждения не должны менять код завершения, потому что не задан `--exit-code`.
- `1` — найдены потенциальные проблемы и указан `--exit-code`.
- `2` — неверный путь или конфигурация, ошибка инициализации Clang либо неполное сканирование из-за ошибок разбора.

Предупреждения Clang могут выводиться в `stderr`, даже если анализатор смог сформировать отчёт. Предупреждение компилятора само по себе не означает, что анализатор завершился с ошибкой.

## Конфигурация правил

Файл `config.json` содержит три основных поля:

```json
{
  "dangerous_functions": {
    "strcpy": "Проверьте длину исходных данных и размер целевого буфера."
  },
  "ignore_paths": ["tests/", "vendor/", "build/"],
  "ignore_comments": ["// ignore-sec", "// nosonar"]
}
```

- `dangerous_functions` — отображение «имя функции → рекомендация».
- `ignore_paths` — имена каталогов, которые нужно исключать из обхода.
- `ignore_comments` — маркеры, которыми можно подавить предупреждение через комментарий C/C++.

Подавления следует использовать осторожно: каждое из них скрывает предупреждение и должно сопровождаться понятным обоснованием.

## Что именно проверяет анализатор

Инструмент ищет вызовы функций, перечисленных в конфигурации. Дополнительно реализованы консервативные проверки для небольшого набора простых сценариев:

- **`strcpy`** — строковый литерал полностью помещается в массив `char` фиксированного размера; поддерживается ограниченный случай простого указателя, инициализированного адресом такого массива.
- **`sprintf`** — часть простых форматных строк с литеральными подстановками `%s` и `%%` может быть рассчитана и сопоставлена с размером целевого массива.
- **`scanf`** — простая строковая спецификация с единственным `%s` и явной шириной считается безопасной только тогда, когда ширина меньше ёмкости целевого массива, оставляя место для нулевого байта.

Если размер буфера, формат или длина данных неизвестны, анализатор по возможности сохраняет предупреждение, а не предполагает безопасность. Эти проверки намеренно ограничены и не являются универсальным анализом указателей или форматных строк.

## Запуск тестов

```bash
python -m unittest -v test_analyzer.py
```

Тесты покрывают проверку конфигурации, исключение каталогов, маркеры подавления, экранирование HTML, нормализацию встроенных имён Clang, ограниченные проверки буферов, метаданные SARIF и обработку ошибок.

Workflow `.github/workflows/tests.yml` дополнительно устанавливает `libclang`, запускает анализ демонстрационного C-файла, проверяет базовую структуру SARIF и сохраняет отчёт как артефакт GitHub Actions.

## SARIF и GitHub Code Scanning

SARIF-отчёт содержит стабильные идентификаторы правил, относительные URI исходных файлов, координаты и фрагменты кода. Совместимые CI- и code-scanning-инструменты могут использовать этот формат.

По умолчанию workflow сохраняет SARIF как артефакт Actions; это **не означает автоматическую публикацию находок в разделе Code scanning**. Дополнительная загрузка в GitHub Code Scanning описана в [`SARIF_USAGE.md`](SARIF_USAGE.md) и требует доступности этой функции для репозитория и соответствующих разрешений.

## Ограничения

- Это не полноценный статический анализатор C/C++: нет межпроцедурного анализа, анализа потока управления и taint/data-flow tracking от источников пользовательских данных до опасных операций.
- Совпадение имени функции не доказывает эксплуатируемость. Например, сам по себе вызов `system("ls")` не означает наличие command injection.
- Проверки размера буферов охватывают только узкие сценарии с известными литералами и массивами фиксированного размера. Сложные алиасы, арифметика указателей и неизвестные значения не анализируются в общем виде.
- Поддержка форматов `scanf` и `sprintf` намеренно ограничена и не моделирует все спецификаторы, типы вариадических аргументов, кодировки и особенности C.
- Флаги компиляции, макросы, пути include и настройки системы сборки влияют на AST. В текущей версии `compile_commands.json` не читается.
- Поддерживаемые расширения исходников: `.c`, `.cpp`, `.h`, `.hpp`, `.cc`.
- Отчёты следует проверять вручную и использовать вместе с диагностикой компилятора, тестами, code review и другими инструментами безопасности.

## Статус проекта

Учебный портфолио-проект для демонстрации навыков работы с Clang AST, написания правил SAST, обработки результатов анализа, разработки регрессионных тестов и настройки CI. Перед использованием как обязательного security gate в production точность и полноту правил необходимо оценить на отдельном наборе размеченных примеров.
